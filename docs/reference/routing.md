# Routing Reference

Every route that exists today — frontend pages and backend API prefixes.

Generated by reading `frontend/src/app/**/page.tsx`, `backend/main.go`, and
`docs/swagger.yaml`. For *why* the frontend is laid out this way, see
[../architecture/frontend.md](../architecture/frontend.md).

## Portals

CrowdFlow runs four portals plus the public site. They are separated by
**Next.js route groups**, which organise files without appearing in the URL.

| Portal | Route group | URL prefix | Session |
|---|---|---|---|
| Public | — | `/` | none |
| Buyer | `(user)` | `/` (no prefix) | user JWT |
| Organizer | `(console)` | `/organizer` | user JWT + `Event Organizer` role |
| Auditor | `(console)` | `/auditor` | user JWT + `Auditor` role |
| Admin | `(console)` | `/admin` | user JWT + admin roles |
| Ticketman | — | `/ticketman` | **separate** ticketman JWT |
| Venue designer | `(venue-designer)` | `/venue-designer` | user JWT + organizer |

Two things to notice, because they trip people up:

- **Buyer pages have no `/user` prefix.** `(user)` is a route group, so the
  profile page is `/profile`, not `/user/profile`.
- **`/ticketman` is outside every group** and runs on its own JWT signing
  secret (`TICKETMAN_JWT_SECRET`). A ticketman token does not verify against
  the user secret and vice versa — that isolation is by construction. See
  [../architecture/auth-and-roles.md](../architecture/auth-and-roles.md).

## Resale — present but switched off

`/resale` and `/resale/[listing_id]` exist as pages, and the backend
`internal/resale` package, `lib/api/resale.ts`, and the
`resale-marketplace/` components are all built and compiling.

**`src/middleware.ts` redirects everything under `/resale` to `/`** by product
decision. The feature is disabled at the edge, not deleted. Re-enabling it is
a one-line middleware change plus a nav entry — but nothing about it is
currently exercised, so treat it as unverified.

## Backend API

`organizer` and `user` packages, which still serve bare `/api/...` paths. This
is a known, deliberate inconsistency — the bare-path calls in `lib/api/` are
**correct** and must not be "fixed".

## Authorization is server-side

Route protection in `middleware.ts` and `AuthGuard` is a **UX affordance**.
Every route above is enforced in the Go middleware; a client that bypasses the
frontend gets a 401/403. Never treat a hidden nav item as a security control.
